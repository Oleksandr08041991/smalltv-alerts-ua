# v3.7.6 — fast volumetric airplane animation, no screen-wide waves

## What changed

- The same detailed aircraft is now rasterized **on the build computer**, not for every output pixel on the ESP8266. The generator compiles the actual `mascotPixel()` polygon code and writes **12 exact 4-bit palette poses** (3 yaw angles × 2 facial expressions × blinking/open eyes) to a generated C++ `PROGMEM` header.
- **111,624 bytes Flash, zero bytes additional persistent frame heap.** Ordinary `smalltv` and `smalltv_lean` PlatformIO builds generate the atlas automatically using `tools/generate_plane_atlas.py`. A host C++ compiler is required; the GitHub CI build provides it.
- The renderer draws **only tiles where the new plane differs from the old** (24 × 12 RGB565 pixels each). It no longer transmits a full-width 4-row strip whenever one pixel changes. Tile staging memory was reduced to 576 bytes.
- Target pacing moved from **5.5 to ~11 FPS** (90 ms per animation step). Actual speed depends on real ST7789/ESP8266 SPI performance, Wi-Fi activity and the number of dirty tiles. Skipped rendering deadlines do not accumulate delays; animation positions use monotonic elapsed time.
- The **20 flight choreographies** remain unchanged: rolling, banking, figure-eights, climbs, dives, approach/retreat and other gestures. Their 3-D effect continues through continuous scaling, yaw, banking and translation of the pre-rasterized plane.
- The compact character on the speech card continues to blink and smile; quotes and author attribution are unchanged.

## Why it should remove the visible wave

Before: every new frame re-evaluated many polygons for both the old and new aircraft across a large screen area, then pushed 4-row *full-width* strips, producing a slow top-to-bottom sweep. Now: packed Flash lookup replaces geometry calculations; unchanged 24×12 tile regions are not transferred over SPI. The display refresh therefore updates only where the aircraft actually changes.

## Installation

After the verified release is published, open GeekMagic → **Система → Перевірити оновлення → Оновити зараз**. The browser fetches the signed/size-checked release metadata and passes the ESP8266 `.bin` to the same-origin device upload endpoint. Do not cut device power while uploading. The device must already support the browser-assisted OTA introduced in v3.7.4; on older firmware the first update may require the manual OTA tab.

## Validation

- `python tools/generate_plane_atlas.py`, `--check` — generated 12-pose raster equals the actual aircraft geometry.
- `node tests/mascot/test_aviation_release.js` — Flash atlas path, 20 movements, tile-level invalidation and pacing.
- `bash tests/update/run.sh`, `node tests/alerts/test_display_refresh.js`.
- `pio run -e smalltv -e smalltv_loader` and firmware size checks.

A compiled artifact and source-level checks do not prove the actual frame rate on a physical ST7789; verify speed and flicker on the device after updating.
